# TS↔Dart parity pairs — the registry

This is one of the **two** registries `scripts/check_parity_pair_registry.mjs`
cross-checks on every PR. The other is the `## The pairs (canonical list)` table
in [`.claude/agents/shared-library-syncer.md`](../../.claude/agents/shared-library-syncer.md),
which is the list the `shared-library-syncer` agent actually works from.

**Adding a pair means editing both, in the same change.** A pair added here with
no row in the syncer table is a pair whose divergence is never detected; a row
there with no entry here reads to a session as a single-platform helper. The
guard fails the PR in either direction, and when either registry names a path
that no longer exists. See [decisions.md § 604](decisions.md).

This file was split out of the root `CLAUDE.md` because it had grown to 115 KB —
about 29,000 tokens re-sent on every single prompt of every session, to carry a
registry that only matters when a session touches one of the pairs. `CLAUDE.md`
keeps the rule and points here; the content below is unchanged.

Read this before editing any pure-logic helper under `apps/web/src/lib/` or
`apps/mobile_android/lib/`, and invoke the `shared-library-syncer` agent after
touching one side of a pair.

Ported 2026-07-11: `age_grade`, `hydration`, `exercise_calories`, `training_paces` (the pace-zone surface of `training`, reusing the watch's ported Riegel), `fitness` (VO2max / VDOT / per-run TSS / recovery advice + the Fitness-card snapshot, with the web's ISO `started_at` + `nowMs` collapsed to an integer day index like `training_load`), then a second batch — `route_markers`, `checkpoint_projection` (reuses the watch's `roadbook::CutoffStatus` + `cutoff_eta::CUTOFF_TIGHT_S`), `route_description` (reuses `distance_bands`), `plan_progress`, `plan_adherence`, `current_week` (ISO dates collapsed to a day index), `nutrition_targets`, `challenge_progress` (reuses `pacer::ON_PACE_BAND`), `badges` (thresholds in lockstep with the SQL awarder; i18n label keys carried as identifiers, not strings), and `locale_defaults`, then a third batch (track / route / race / training) — `privacy` (`clipPointsToZones`), `segments` (segment effort + competition-rank + crown label), `track_projection`, `run_heatmap` (`buildHeatCells` + `heatBounds`; the MapLibre GeoJSON emitters are web-only), `relink_candidates` (dates collapsed to a day index), `live_freshness`, and `finisher_certificate` (the shaping half; the SVG/PNG builder is web-only). Ported 2026-07-28: `workout` — the mobile `run_recorder` `WorkoutRunner` state machine (a shipped-phone-engine port, not a web pair), executing `WKT1`-pushed pre-expanded steps with its own glance page + lap-press step-skip (decisions § 354; the Dart `watch_workout.dart` encoder + iOS twin pin the shared golden vectors), and `daylight` (the seasonal sunrise/sunset half of `safety_nudge` — Cooper's declination, the −0.833° horizon, the polar clamps — driving the watch's tz-gated Daylight countdown page, decisions §355). **The 2026-07-29 batch is watch-native, not ported at all** — three parity rows with no web twin to mirror: `waypoints` (an eight-slot newest-wins mark store + `WPT1` codec behind BTN5's hold, decisions §357), `ice` (the ICE / medical-ID card on `SET1` v6 + an `ICE1` flash record, rendered as a third idle face, decisions §358), and `climb` (live ascent segmentation plus the ClimbPro-style crest ahead read off the already-pushed course profile, decisions §359). Nothing in that batch belongs in the parity-pair list above: adding a web twin later would be a *new* web feature, not a sync obligation. **Watch-native again 2026-07-30, three at once:** `sleep_station` (decisions §373) — the nap budget a 200-mile racer can afford before the next cut-off, computed as `cutoff_eta`'s margin less a reserve and inheriting its refusal to project off a stale fix; `timers` (decisions §375) — a countdown + stopwatch as one instrument behind an idle BTN2 modal, whose ADR also records why an **alarm** and a **find-my-phone** were refused rather than built; and `backyard` (decisions §372) — the wall-clock-anchored corral bell, the loop count riding the recorder's lap, the learned loop length and the projected return margin. None of the three has a web twin, and none is owed. **Watch-native once more 2026-07-31:** `storm` (decisions §376) — baro-driven storm detection, which trends a GPS-compensated **sea-level reduction** rather than raw station pressure because on a mountain ultra a 500 m climb moves the barometer twenty times further than a front does, and which refuses outright (`NO ALT REFERENCE`) when no GPS altitude corroborates the sensor rather than reporting a climb as weather. No web twin and none owed — the phone has no barometer.
